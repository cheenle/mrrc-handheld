# 麦克风诊断报告 — coolkit-xz-02

> 结论先说：**这台设备的麦克风在语音频带（300–2700 Hz）几乎没有响应，
> 属于器件/声学层面的问题，软件无法修复。** 下面每一行都有实测数据。

## 1. 已经排除的环节（都有测量依据）

| 环节 | 证据 | 结论 |
|---|---|---|
| I2S 接线与引脚 | 用 JTAG 读**原厂固件运行时的 GPIO matrix 寄存器**：`GPIO5←sig31(I2S1_BCK)`、`GPIO4←sig32(I2S1_WS)`、`sig30(I2S1_SD)←GPIO6`；功放为 `GPIO15/16/7` | 与原厂一致 ✅ |
| 电源保持 | 原厂 GPIO21 用 **RTC-IO** 方式驱动（数字寄存器读到 0 是正常现象） | 已按 RTC 方式驱动 ✅ |
| 接收通路本身 | 把 DIN 路由到我们自己翻转的 GPIO12，立刻读到 `pk_raw=134217727` | 接收通路正常 ✅ |
| 采样率 | `frames=16320/s`（16 kHz，满帧） | ✅ |
| 位对齐 | 原始 32 位字集中在 bit13–24，低 13 位恒 0 → `>>12` | ✅ |
| 双字/采样 | 每采样 2 个字（左右槽都传），已去交织，否则音调低八度 | ✅ 已修 |
| DSP 频带 | `txdiag` 三段能量；安静时输出直流 `dc_out=0` | ✅ |
| 编码/服务端 | 上行 48 kHz Opus（与手机浏览器同参数）；服务端 `frames/fed/written` 无丢弃 | ✅ |

## 2. 麦克风实测频响（设备自己放音、自己录）

固件在扬声器上依次播放单音，同时用 Goertzel 在麦克风信号里测该频点幅度
（`CONFIG_MRRC_ACOUSTIC_SWEEP=y` 可复现）：

```
  200 Hz -> mic response  1.2
  400 Hz -> mic response  6.4
  800 Hz -> mic response  2.7
 1000 Hz -> mic response  2.3
```

满量程是 32768。也就是**扬声器贴着麦克风放 13% 满幅的单音，麦克风只回 2~6 个计数**
（约 -75 dBFS）——正常 I2S MEMS 麦在这种耦合下应该回几百到几千。

## 3. 三段能量实测（`txdiag`，每 2 秒一行）

| 场景 | in（去直流输入） | <300 Hz | **300–2.7k** | >2.7k |
|---|---|---|---|---|
| 安静 | 83~160 | 78~150 | **12** | 25 |
| 20 cm 正常说话 | 120~160 | 110~150 | **13** | 48 |
| 5~10 cm 大声说话 | 480~2133 | 478~2131 | **16~21** | 67~77 |
| 手机贴耳放音乐 | 550 | 548 | **36** | 26 |

**说话时 300–2.7 kHz 的能量没有任何变化**（12 → 13~21），而 300 Hz 以下能涨 10 倍以上。
麦克风能拾到"低频振动/结构传导"，但**语音频带是聋的**。

## 4. 为什么软件救不回来

- 语音带内 信号≈18 / 底噪≈12 → **信噪比只有约 3~6 dB**
- 放大只会把底噪一起放大：把 AGC 上限抬到 +36 dB 后，输出 `>2.7k` 噪声从 25 涨到 **100**
  （听感就是"有功率但全是噪音"）
- 高通从 1 阶换到 2 阶（350 Hz）、加低通 3 kHz、加噪声门：都做了，只能改善频带，
  **无法凭空创造信噪比**

## 5. 交叉验证

原厂小智固件恢复后（逐字节还原，设备在线 `192.168.1.236`）**同样唤醒不了** →
不是本固件造成，也不是配置错误。

## 6. 建议的硬件处理

1. 检查**外壳麦克风开孔**：防尘网/泡棉/贴膜/结构挡板是否堵住（最常见的"整机听不见"）
2. 拆开确认麦克风器件：常见 I2S MEMS（如 ICS-43434）焊在板上，带小孔；
   看焊点是否虚焊、器件是否被贴片胶/三防漆覆盖
3. 有条件时更换麦克风并重新执行 `CONFIG_MRRC_ACOUSTIC_SWEEP=y` 复测——
   正常器件在 400–1000 Hz 应回几百以上
4. 若短时间无法换件：当前固件已把 AGC 上限压回 +24 dB、门限 1%，
   **安静时不会把噪声发到空中**（宁可不发射，也不发噪声）
